# 开发日志

## 当前阶段进度（2026/3/29-2026/3/30）

### 本阶段目标
这一阶段的核心目标，是把项目从一个空的 Unity 2D 工程，推进到一个可以实际测试核心玩法的原型阶段。

目前重点集中在三件事上：
- 搭建角色的基础控制与挥剑反弹原型
- 建立可扩展的房间式地图数据结构
- 制作一套可以直接用于内容生产的房间编辑器

### 已完成内容

#### 1. 玩家基础控制器
目前已经完成了一套自定义的 2D 玩家控制器，没有把角色运动完全交给 Unity 刚体物理。

当前支持：
- 左右离散移动
- 空中横向控制
- 重力下落
- 最大下落速度限制
- 地面接地检测与贴地修正
- 横向停下时按 `0.1` 单位对齐位置
- 可单独调整角色实际碰撞体大小

这一套控制器的目的，不是做传统平台跳跃，而是为后续“挥剑命中后反弹移动”的核心玩法服务。

#### 2. 输入系统
项目已经切换到 Unity 的 `Input System`。

当前输入方案已经统一支持键盘、鼠标与手柄：
- `WASD` / 左摇杆 / 十字键：移动
- 鼠标左键 / 空格 / 手柄 `A`：主能力
- 鼠标右键 / 手柄 `X`：副能力
- `Tab` / 手柄 `LB`：地图相关输入

输入层已经单独拆出，不和角色移动、挥剑逻辑硬绑定，后续做重绑定或扩展输入时会更容易。

#### 3. 挥剑系统
挥剑逻辑已经从角色控制器中拆出，形成独立的武器组件。

当前已实现：
- 四方向挥剑判定
- 不按上下时按最后左右朝向攻击
- 按上时向上砍
- 按下时向下砍
- 剑的命中检测
- 命中后触发角色反弹
- 攻击判定盒调试可视化

这部分目前的重点是先验证玩法和手感，而不是最终表现。

#### 4. 反弹 / Recoil 原型
项目的核心移动机制已经开始围绕“挥剑命中后的反弹”构建。

当前已实现：
- 命中碰撞体后按攻击反方向反弹
- 水平反弹与竖直反弹分开配置
- 可调整反弹距离、持续时间、曲线、退出速度
- 水平反弹期间可锁定横向输入
- 竖直反弹期间可允许横向控制
- 反弹与普通移动系统分离，方便后续继续打磨

这部分已经是玩法原型的核心之一，但手感仍然处于持续调整阶段。

#### 5. 单向平台
地图中已经加入新的格子类型 `OneWayPlatform`。

当前单向平台具备这些基础规则：
- 显示在单个格子的上半部分
- 玩家可以从下方穿过
- 玩家可以从上方站上去
- 玩家可以用剑砍到单向平台
- 在特定反弹状态下，可短时间穿过单向平台

目前单向平台已经能参与运行时生成与测试，但它的碰撞细节和视觉一致性仍然需要继续打磨。

#### 6. 房间地图数据结构
项目地图已经不是直接手工堆在 Scene 里，而是开始使用数据驱动方式组织。

当前结构为：
- 一个 `MapDefinition` 作为整张地图的数据容器
- 多个 `MapRoomDefinition` 作为独立房间数据
- 每个房间固定尺寸为 `20 x 15`

每个房间当前可保存：
- 房间 ID
- 房间名
- 是否允许在地图中显示
- 每个格子的格子类型

当前支持的格子类型：
- `Empty`
- `Wall`
- `Ground`
- `OneWayPlatform`

#### 7. 运行时地图生成
编辑器中编辑的房间内容，已经能够生成到运行时场景中进行测试，而不是只停留在预览层。

当前生成内容包括：
- 可见格子
- 实际碰撞体
- 单向平台标记

也就是说，编辑器中画出来的地面与墙体，已经可以被玩家直接用于测试移动、碰撞和挥剑。

#### 8. 基于房间的相机与视口方案
目前已经有基础的房间相机控制方案。

当前支持：
- 根据玩家位置识别其处于哪个房间
- 相机锁定到当前房间中心
- 所有房间保持激活，不会因为切换房间而关闭
- 通过视口遮罩方案，仅显示当前房间区域

这样做的原因，是为了兼容“全图机关可能同时生效”的设计需求。

#### 9. 地图编辑器
项目已经有一套自定义地图编辑工作流，而不是完全依赖原生 Tilemap 手工搭建。

当前已完成：
- 地图编辑根对象 `MapAuthoringRoot`
- 房间资源自动创建
- 房间在世界中的放置
- 房间内容的实时编辑
- 编辑结果实时刷新到运行时测试层

同时，重复在同一坐标新建房间时，已经开始朝“优先复用同名房间资源”的方向收口，避免无意义的重复资源堆积。

#### 10. 独立的 Room Editor 窗口
除了 Scene 内编辑外，目前也已经实现了独立的 `Room Editor` 编辑窗口。

当前窗口已支持：
- 编辑当前房间的 `20 x 15` 网格
- 左键绘制、右键擦除
- 使用 `1 / 2 / 3 / 4` 快捷键切换笔刷
- 直接编辑房间名
- 左侧编辑当前房间
- 右侧查看粗略世界总览

右侧世界总览当前支持：
- 按房间在世界中的相对位置进行展示
- 选中区域
- 在空区域创建新房间
- 用当前房间覆盖某区域
- 删除某区域的房间
- 右键拖动查看其他区域

这套工具的目标，是逐步形成适合大型项目持续扩展的地图制作工作流。

### 当前存在的问题
虽然目前已经进入可测试原型阶段，但还有不少部分只是“可用”，还没有达到稳定状态。

当前比较明确的问题有：
- 单向平台的碰撞与表现仍需进一步统一
- 反弹手感仍需要持续打磨
- 世界总览与房间编辑器的交互还需要继续优化
- 房间视口遮罩现在是功能优先，还不是最终表现方案
- 地图系统目前还没有加入正式的房间连接、门、存档与探索 UI

### 当前阶段的意义
到目前为止，项目已经完成了从“空工程”到“可玩原型骨架”的过渡。

现在已经具备：
- 一个可实际测试的角色控制原型
- 一套围绕挥剑反弹构建的核心玩法基础
- 一个可扩展的房间地图数据结构
- 一条从地图编辑到运行时测试的完整工作流

这意味着接下来不再只是验证“能不能做”，而是可以开始持续验证：
- 关卡是否好玩
- 房间结构是否合理
- 反弹机制是否真的能支撑完整地图设计

### 下一步计划
接下来的重点会继续围绕“把原型打磨成稳定的可扩展基础”展开。

下一步优先方向：
- 继续打磨单向平台与反弹相关规则
- 完善房间连接与切换逻辑
- 补充地图探索与显示机制
- 优化编辑器交互体验
- 持续打磨玩家控制和相机表现


## 开发进度更新（2026/3/31）

### 本次重点
今天的开发重点主要放在三个方向上：
- 为玩家加入第二个核心能力“长枪”
- 继续扩展地图格子类型与对应的运行时规则
- 进一步整理编辑器与能力系统的代码结构

### 已完成内容

#### 1. 第二核心能力：长枪
目前已经完成了一版可测试的长枪原型，作为玩家的第二个核心能力接入。

当前已实现：
- 鼠标右键 / 手柄 `X` 触发长枪能力
- 短按：按当前四方向直接投出长枪
- 长按：进入子弹时间，松开发射长枪
- 长枪飞行、插入、牵引、提前取消牵引、破碎、回收这一整套状态链
- 长枪飞行超过 `3` 秒时自动破碎
- 长枪插入表面后，露在外面的长度固定为 `1` 格
- 长枪插住后再次按键，可将玩家向长枪位置牵引
- 牵引过程中再次按键，可提前终止并保留当前方向速度
- 牵引过程中撞到障碍时，长枪破碎并结束牵引

这意味着项目的“第二能力”已经不再只是概念，而是进入了可反复测试和继续调手感的阶段。

#### 2. 长枪与单向平台规则
长枪插入后的交互继续向正式玩法靠拢。

当前补充完成：
- 水平插入的长枪可以作为单向平台使用
- 插住的长枪可以被剑命中
- 被剑命中后，玩家会正常反弹，同时长枪破碎
- 单向平台的有效挥砍方向开始按“平台朝向”判断，而不是统一处理

具体来说：
- 水平单向平台：只有上下砍才有效
- 竖直单向平台：只有左右砍才有效

这样做是为了让普通单向平台和“插在墙上的长枪平台”都能复用同一套规则，而不是后面不断堆特判。

#### 3. 新的地图格子类型
今天继续扩展了地图编辑器可用的格子种类，并将它们接到了运行时逻辑中。

新增格子包括：
- `Death`
- `SavePoint`

对应规则为：
- 玩家碰到死亡格子后会死亡
- 玩家死亡后会从当前唯一激活的存档点复活
- 若当前没有激活存档点，则回到初始出生位置
- 存档格子本身没有实体碰撞，但会作为触发区域激活存档

同时还补充了以下联动规则：
- 飞行中的长枪碰到死亡格子会破碎
- 剑砍死亡格子不会反弹
- 玩家死亡时，如果场上还有长枪，则长枪会一并破碎回收

#### 4. 编辑器支持与快捷键
房间编辑器也随着新格子的加入同步扩展。

当前已补充：
- `Death` 与 `SavePoint` 的可视化绘制
- 快捷键：
  - `5` = `Death`
  - `6` = `SavePoint`
- 房间名称可直接在 `Room Editor` 中修改
- 世界总览中的区域选择、创建、替换、删除流程继续完善

目前房间编辑器已经逐渐从“能用的原型工具”向“适合长期扩展的内容生产工具”靠近。

#### 5. 能力解锁入口
考虑到这两个核心能力都需要随着关卡推进逐步获得，今天也把“能力解锁”从临时逻辑整理成了正式入口。

当前已完成：
- 给剑与长枪都加入了可锁定 / 可解锁接口
- 新增统一入口 `PlayerAbilityLoadout`
- 玩家现在可以在开局时没有剑或没有长枪
- 后续可以通过关卡事件、触发器或剧情逻辑单独开启对应能力

这一步的意义在于：后面做能力获取、能力门、能力成长时，不需要再直接操作具体脚本内部状态。

#### 6. 代码重构
今天也做了一轮结构整理，重点是把容易继续膨胀的部分拆出职责边界。

本次重构包括：
- 为玩家能力引入统一解锁接口 `IPlayerUnlockableAbility`
- 让 `PlayerSword` 与 `PlayerSpear` 共享这套能力启用/禁用协议
- 将 `Room Editor` 中的主题色与格子配色抽到独立的编辑器主题工具
- 将世界总览的边界计算、房间矩形换算、区域命中逻辑抽到独立工具类

这类整理并不会立刻带来新玩法，但会直接降低后续继续加规则时的耦合度。

### 当前存在的问题
虽然今天补上了不少玩法链路，但目前仍然还有明显需要继续打磨的部分：
- 长枪平台与单向平台的碰撞细节仍然需要继续修整
- 长枪牵引的速度曲线与整体手感还处在原型阶段
- 地图编辑器虽然已经更顺手，但世界总览仍有继续优化空间
- `PlayerController2D` 仍然是当前项目里最大的核心文件，后面还需要专门再做一次拆分

### 本阶段的意义
今天最大的推进，不是单独多了一个“长枪功能”，而是项目开始形成“双核心能力 + 地图格子规则 + 编辑器生产工具”三者联动的结构。

这意味着接下来可以开始更认真地验证：
- 两个核心能力是否能够真正支撑关卡设计
- 不同格子与能力之间的组合是否足够丰富
- 当前编辑器工作流是否已经足以支撑后续持续做内容

### 下一步计划
接下来优先考虑继续推进这些方向：
- 继续打磨长枪的飞行、插入、牵引与破碎手感
- 继续完善单向平台与长枪平台的边界交互
- 补充能力获取触发器与能力门逻辑
- 进一步拆分 `PlayerController2D`，降低核心控制器的复杂度
- 持续优化 `Room Editor` 和世界总览的内容制作体验

## 开发进度更新（2026/6/22 - 2026/6/25）

这一段记录的是上一版开发文档之后继续推进的内容，主要集中在地图编辑器、运行时大地图、长枪能力、子弹时间、可破坏方块，以及围绕这些系统做的重构和体验修正。

### 1. 运行时大地图

这几天补上了游戏内按键展开地图的功能。玩家现在可以通过 `Tab`，以及手柄的 `LB`，打开全屏地图界面。这个界面不再只是一个很小的提示框，而是会铺满屏幕，用更接近游戏内地图界面的方式展示当前世界的粗略结构。

地图显示逻辑也做了优化：房间的缩略信息不会在每次打开地图时重新临时计算，而是在编辑阶段或房间数据变化时缓存下来。这样游戏运行时打开地图只需要读取已有的粗略图数据，避免因为实时重建地图导致卡顿。

目前大地图已经支持：
- 全屏背景遮罩，让地图界面有独立的视觉层级。
- 显示房间的大致结构，而不是只显示空白矩形。
- 标记当前所在房间。
- 根据房间数据绘制墙、地面、单向平台、死亡格、存档点、可破坏方块等粗略细节。
- 打开地图时冻结游戏输入和游戏过程，避免玩家在看地图时角色继续行动。

这一步的意义是，地图系统开始从“编辑器里的辅助视图”变成“游戏中可用的探索反馈”。之后它可以继续扩展成真正的银河恶魔城地图，包括已探索区域、未探索区域、当前房间、高亮目标点、能力门提示等。

### 2. 地图编辑器体验优化

地图编辑器继续做了很多面向实际内容制作的改进。之前的问题是，编辑一个房间时只能看到当前房间，很难判断它和相邻房间之间是否对齐。现在房间编辑视图已经加入了相邻房间的参考显示：当前房间仍然是主要编辑对象，但周围房间的内容会以参考层的形式显示出来，方便对齐通道、平台高度、墙面边界和房间连接关系。

编辑器窗口也做了布局优化：左侧主要用于当前房间编辑，右侧用于世界概览。世界概览不再只是一个静态预览，而是可以帮助选择世界中的房间和区域。整体布局也开始根据窗口大小自适应，避免固定窗口尺寸时出现大量空白或拥挤的问题。

这几天补上的编辑器能力包括：
- 在 `World Overview` 中选择世界区域。
- 对选中的区域执行 `Select`、`New Room`、`Replace`、`Delete`。
- 支持选择空区域，用于在新位置创建房间。
- 支持用当前房间覆盖已有区域。
- 支持删除世界中某个区域的房间放置。
- 支持直接在编辑器中修改房间名字。
- 默认隐藏不必要的说明栏位，让界面更干净。
- `Follow Selection` 默认开启，不再作为常驻设置项占用界面空间。
- 颜色做过多轮调整，让墙、地面、单向平台、死亡格、存档点和可破坏方块更容易区分。

### 3. 编辑器 Undo / Redo 与测试入口

地图编辑器开始补齐更完整的编辑器工作流。现在绘制格子、创建房间、替换房间、删除房间、修改房间名字等操作都接入了 Unity 的 Undo / Redo 系统。这样做内容时如果误操作，可以直接撤销，而不是手动恢复数据。

还加入了测试入口相关功能：
- `Move Player Here` 会把玩家移动到当前选中房间的测试出生点。
- 如果房间内存在存档点，则优先把玩家移动到第一个存档点位置。
- 如果房间里没有存档点，则退回到房间中心。
- `Play Here` 会先移动玩家，再进入 Play Mode，方便快速测试某个房间。

这个功能解决了一个很实际的问题：大地图越来越大后，测试某个房间不应该每次都从默认出生点慢慢跑过去。以后做关卡时，可以直接从编辑器跳到目标房间测试。

### 4. 新格子：可破坏方块

加入了新的格子类型：可破坏方块。它在编辑器中显示为褐色，在游戏中显示为浅褐色，并且每个格子使用圆角正方形的视觉表现，让它和普通墙体、地面、单向平台明显区分。

可破坏方块的规则是：
- 它具有碰撞体，玩家不能直接穿过。
- 它可以被剑砍中。
- 被砍中后，所有与它连在一起的可破坏方块会一起消失。
- 消失范围按同一个房间实例内的连通块计算，避免影响不相关位置的同类方块。

这让地图开始拥有更强的“能力交互”空间。之后可以用它制作需要剑能力打开的临时通路、隐藏路径、捷径、一次性破坏结构，或者和长枪能力组合形成更复杂的谜题。

### 5. 长枪能力调整

第二核心能力长枪继续迭代。原本右键长按会进入子弹时间，松开后发射长枪；现在这个逻辑被拆开了。长枪不再依赖长按蓄力，而是按下右键或手柄 `X` 时立即发射。

长枪当前规则包括：
- 按下能力键立即发射。
- 长枪按玩家当前输入方向或朝向飞出。
- 飞行中碰到可插入物体会插入。
- 插入后，玩家再次按下能力键会向长枪位置牵引。
- 牵引过程中再次按键可以提前取消牵引，并保留方向速度。
- 牵引途中撞到障碍会让长枪破碎并结束牵引。
- 长枪飞行超时会破碎。
- 长枪碰到死亡格会破碎。
- 玩家死亡时，场上已有的长枪也会破碎。
- 水平插入的长枪可以作为单向平台。
- 长枪插入后可以被剑砍碎，但会根据插入方向过滤不合理的命中方向。

这些调整让长枪的职责更清晰：它主要负责远距离投掷、固定点牵引、临时平台，以及和剑产生交互，而不再同时承担子弹时间入口。

### 6. 子弹时间独立成能力

子弹时间从长枪长按逻辑中拆出来，改成独立能力。现在玩家通过按住 `Ctrl` 或手柄 `RT` 进入子弹时间。这样长枪发射和子弹时间不再互相绑定，玩家可以在需要瞄准、观察或调整操作节奏时主动进入子弹时间。

这一部分还修复了几个手感问题：
- 子弹时间下发射长枪时，长枪的真实持续时间会随着时间缩放延长，而不是仍按原真实时间消失。
- 子弹时间下牵引玩家时，牵引路径需要和正常时间保持一致。
- 牵引过程可以受到子弹时间影响，表现为速度变慢，但运动路线不应该改变。
- 修正了牵引中被地面吸附或落地修正干扰的问题。

最终目标是：子弹时间只改变“时间流速”，不改变规则本身。玩家在慢动作里看到的应该是同一条路径，只是过程更慢、更容易操作。

### 7. 死亡格、存档点与能力状态

死亡格和存档点也继续被整合进游戏循环。死亡格是有碰撞体的危险格子，玩家碰到就会死亡，不能像普通地面一样站在上面。存档点没有普通阻挡体积，玩家接触后会激活该存档点；死亡后从当前激活的存档点复活。

这部分还补充了死亡时的联动逻辑：如果玩家死亡时场上有长枪，长枪会破碎并回收，避免复活后场景里留下错误状态。

能力方面也加入了启动接口。剑和长枪作为核心能力，不应该从游戏一开始就默认全部可用，而是可以随着关卡推进被解锁。现在代码层面已经开始支持能力启用 / 禁用，为之后制作能力获取点、能力门和知识锁关卡打基础。

### 8. 代码重构与清理

这几天也做了多轮重构，重点是把越来越复杂的系统拆开，避免单个脚本继续膨胀。

地图编辑器部分被拆分出多个职责更明确的辅助类：
- 布局计算。
- 房间网格绘制。
- 世界概览交互。
- 工具栏行为。
- 测试入口逻辑。
- 编辑器资源创建与复用。

玩家与能力部分也做了整理：
- 长枪逻辑和子弹时间逻辑解耦。
- 牵引运动拆成更小的计算函数。
- 修复了 `RuntimeMapDisplay` 中隐藏 Unity 内置成员导致的 warning。
- 对近期新增的地图 UI 和编辑器逻辑做了编译检查。

目前项目的方向已经更明确：
- 玩家核心移动和剑反弹是第一层能力。
- 长枪和牵引是第二层能力。
- 地图编辑器用于快速生产房间和世界结构。
- 运行时地图用于反馈玩家探索进度。
- 不同格子类型开始承担不同关卡语义。

### 9. 当前仍需继续打磨的问题

虽然系统已经越来越完整，但还有一些明显需要继续优化的点：
- 地图编辑器的窗口利用率和交互手感还可以继续提升。
- 世界概览需要更接近正式游戏地图的表现，而不只是编辑器预览。
- 可破坏方块未来可能需要动画、音效和粒子反馈。
- 长枪牵引、取消、破碎的反馈还需要更强的视觉提示。
- 能力解锁接口已经有了，但还需要实际的能力获取物和关卡门设计。
- `PlayerController2D` 虽然已经拆出了一部分逻辑，但仍然是核心复杂脚本，后续可以继续拆分移动、碰撞、状态、外力和能力响应。

### 本阶段总结

6.22 到 6.25 这一段，项目从“核心机制原型”进一步推进到了“可以开始持续制作关卡内容”的阶段。地图编辑器能更方便地编辑房间和世界结构，游戏内地图开始承担探索反馈，长枪和子弹时间被拆成更清晰的能力，可破坏方块让关卡交互更加丰富。

接下来最重要的不是继续无限堆功能，而是开始用这些工具做小规模测试关卡。只有把剑、长枪、死亡格、存档点、可破坏方块和地图连接真正组合起来，才能判断这些系统的手感、节奏和关卡潜力是否成立。
